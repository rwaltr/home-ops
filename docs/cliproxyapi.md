# CLIProxyAPI

`router-for-me/CLIProxyAPI` — a proxy that exposes CLI-assistant subscriptions
(Codex/ChatGPT, Claude Code, Gemini) as OpenAI-, Anthropic- and Gemini-compatible
endpoints, with multiple accounts behind one address and round-robin between them.

Deployed at `infra/k8s/kyz/apps/default/cliproxyapi/`, service
`http://cliproxyapi.default.svc.cluster.local:8317`. Cluster-internal: agentgateway
is the front door, nothing else reaches it, and no HTTPRoute exists.

## The split that matters

| what               | where                        | why                                                         |
| ------------------ | ---------------------------- | ----------------------------------------------------------- |
| the front-door key | 1Password item `cliproxyapi` | generated by `infra/terraform/bootstrap/cliproxyapi.tf`     |
| provider sessions  | PVC `cliproxyapi-auth`       | OAuth tokens that rotate; a Secret mount breaks the refresh |
| the config         | `cliproxyapi-config` Secret  | rendered from the item at `/etc/cliproxyapi`, read-only     |

Config lives in the ExternalSecret's template, so it is reviewed in git while the
one value in it is not. `management.disable-control-panel: true` and no admin API:
a second web surface on a homelab box buys nothing.

## Logging in — the one unavoidable human step

Each provider is an OAuth account. The browser authorises it once; the proxy
receives a token pair, stores it in `oauth.auth-dir` (`/data/.cli-proxy-api`, on
the PVC) and refreshes it from then on. `pods/exec` is deliberately absent from
Teletran's RBAC, so this is rwaltr's to run:

```sh
kubectl -n default exec -it deploy/cliproxyapi -- /CLIProxyAPI/CLIProxyAPI --codex-login
kubectl -n default exec -it deploy/cliproxyapi -- /CLIProxyAPI/CLIProxyAPI --claude-login
kubectl -n default exec -it deploy/cliproxyapi -- /CLIProxyAPI/CLIProxyAPI --gemini-login
```

`HOME=/data` is set so anything the process writes relative to home lands on the
PVC and survives a pod roll. After a login, `ls` inside the pod shows a JSON file
per account in the auth dir.

**Until then the proxy runs and serves nothing.** That is the expected empty
state: the pod is Ready because it is listening, and every request is rejected for
want of an upstream. If a provider later stops working, the usual cause is an
expired refresh token — re-run the matching `--*-login`.

## Checking it

```sh
kubectl -n default logs deploy/cliproxyapi --tail=50
```

Once a login exists, an OpenAI-compatible call with the front-door key works from
inside the cluster:

```sh
curl -s http://cliproxyapi.default.svc.cluster.local:8317/v1/models \
  -H "Authorization: Bearer $(op read 'op://home-ops/cliproxyapi/password')"
```
